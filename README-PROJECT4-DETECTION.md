# Cyranta Project 4.1 — CYR-DET-001 Offline Detection Starter

## Scope

This is a **new**, independent detection module. It does not modify `app/main.py`,
`app/telemetry.py`, `agent/security/tool_gateway.py`, or the Project 2 RAG code.
It consumes the **existing** Cyranta Project 1 chatbot JSONL events.

CYR-DET-001 fires only when:
- `event_type == "llm_request"`
- `blocked is True` (actual JSON boolean)
- `request_id` is a valid UUID
- `ts` is a valid timezone-aware ISO-8601 timestamp

Do **not** call this an automatic prompt-injection detection: the existing
`blocked` field signals that application controls blocked a request, which
may happen for several reasons.

The detector ignores other event types, reports malformed lines as counts,
deduplicates by rule ID + request ID, and outputs only a fixed allowlist:
`alert_id`, `rule_id`, `severity`, `event_type`, `request_id`, `event_ts`, `reason`.
It never copies prompts, responses, injection indicators or user IDs.

The scanner writes alerts atomically and replaces the output at every run. This
is a deliberate offline snapshot, **not** a continuous tailer or a SIEM ingest.

## Install safely on Windows PowerShell

From `C:\AI-Security\cyranta-ai-security-lab`:

```powershell
if ((git branch --show-current) -ne 'project4-monitoring-detection') { throw 'Wrong branch' }
if (git status --porcelain) { throw 'Working tree not clean' }

$zip = Join-Path $env:USERPROFILE 'Downloads\cyranta-project4-detector-starter.zip'
$stage = Join-Path $env:TEMP 'cyranta-project4-detector-starter'
Expand-Archive -LiteralPath $zip -DestinationPath $stage -Force

if (Test-Path monitoring) { throw 'STOP: existing monitoring/ directory; review manually' }
if (Test-Path README-PROJECT4-DETECTION.md) { throw 'STOP: README already exists' }
Copy-Item (Join-Path $stage monitoring) . -Recurse
Copy-Item (Join-Path $stage 'README-PROJECT4-DETECTION.md') .
```

## Tests (offline; no Ollama, Chroma or external network)

```powershell
$py = '.\.venv-agent\Scripts\python.exe'
& $py -m pytest monitoring/tests -q
& $py -m ruff check .
& $py -m pytest -q
```

The new tests cover rule triggering, benign events, malformed JSON, strict
boolean validation, valid UUID/timestamps, duplicate event IDs, non-leakage,
output replacement and safe handling when input is missing.

## Run a synthetic demo (no real prompts)

```powershell
New-Item -ItemType Directory telemetry -Force | Out-Null
$demo = @'
{"event_type":"llm_request","blocked":true,"request_id":"d53a9cba-9f19-4b9e-a8fe-6c63b9ce8fc0","ts":"2026-10-13T16:00:00+00:00","status":"blocked"}
{"event_type":"llm_request","blocked":false,"request_id":"93ef9d93-2b59-4edf-b870-09493d72bc24","ts":"2026-10-13T16:01:00+00:00","status":"allowed"}
'@
$demo | Set-Content -LiteralPath telemetry\project4-demo.jsonl -Encoding UTF8
& $py -m monitoring.detector --input telemetry\project4-demo.jsonl --output telemetry\project4-demo-alerts.jsonl
Get-Content telemetry\project4-demo-alerts.jsonl
```

Expected summary: one alert, one ignored event. `telemetry/*.jsonl` is excluded
from Git in the existing `.gitignore`.

The detector reads UTF-8 with or without a PowerShell-generated byte-order mark.
If you want to process real local events, set `--input` to
`telemetry/events.jsonl`. The resulting file contains sanitized alerts only,
but the **source** may include sensitive material and must not be uploaded.

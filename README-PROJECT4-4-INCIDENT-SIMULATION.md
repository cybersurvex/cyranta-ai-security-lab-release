# Cyranta Project 4.4 — Offline SOC Incident Simulation

This add-on reuses **the existing** Project 4 detector (`monitoring.detector.scan_jsonl`), gateway audit normalizer (`normalize_gateway_audit`), and offline dashboard (`monitoring.dashboard.generate`). No production Agent tool authorization logic is modified, no network connections are opened, and no LLM is contacted.

## Four controlled scenarios

| ID | Event source | Expected detector | Meaning |
|---|---|---|---|
| SIM-LLM-001 | Synthetic blocked chatbot event | CYR-DET-001 | Tests alert pipeline, **not a live prompt-injection exploit** |
| SIM-GATE-006 | Real local `ToolGateway.execute` denial | CYR-DET-006 | Read-only actor tries a forbidden refund |
| SIM-GATE-007 | Real local `ToolGateway.execute` denial | CYR-DET-007 | Supervisor approval expires before a simulated refund; **not proof of replay** |
| SIM-CTRL-000 | Real local authorized mock gateway lookup | No alert | Benign negative control |

All orders, identities and tools are in-memory *fictional* fixtures. The 4.4 generator writes only an allowlisted normalized event schema. It does not persist raw gateway logs, sensitive principals, tool arguments, customer records or capability/approval bearer tokens.

## Installation

On `project4-incident-simulation`, unpack `cyranta-project4-4-incident-simulation.zip` into a **separate temporary folder**. Copy only:

```text
monitoring/incident_simulation.py
monitoring/tests/test_incident_simulation.py
monitoring/playbooks/CYR-IR-001.md
README-PROJECT4-4-INCIDENT-SIMULATION.md
```

Add this to `.gitignore` (preserving existing exclusions):

```text
telemetry/incidents/
```

## PowerShell validation and demonstration

```powershell
cd C:\AI-Security\cyranta-ai-security-lab
$py = '.\.venv-agent\Scripts\python.exe'
& $py -m ruff check .
& $py -m pytest monitoring/tests -q
& $py -m pytest -q

# Choose an unused directory; the runner will not overwrite evidence.
& $py -m monitoring.incident_simulation run `
    --output-dir telemetry\incidents\project4-demo-001

& $py -m monitoring.incident_simulation verify `
    --output-dir telemetry\incidents\project4-demo-001

Start-Process (Resolve-Path 'telemetry\incidents\project4-demo-001\dashboard.html').Path
```

Expected run summary:

```json
{"alerts": 3, "all_expected_detections_matched": true, "benign_controls": 1, "scenarios": 4}
```

A new directory contains:

- `events.jsonl` — **synthetic/fictional** sanitized detector inputs.
- `alerts.jsonl` — 3 detected alerts generated by the existing detector.
- `dashboard.html` — local snapshot of the **simulation only**.
- `case-report.json` — 4 scenario records with expected vs observed rules and explicit non-incident classification.
- `incident-report.md` — SOC-style investigation timeline, interpretation and evidence gaps.
- `evidence-manifest.json` — SHA-256 hashes for the other five evidence files.

The verified evidence set is intended to remain unchanged. Editing a dashboard or case report will correctly cause `verify` to fail; create another run directory if you need a new baseline. The manifest is **unsigned**; hashes alone cannot prove provenance or who created the evidence.

## Important boundaries

- **No production incident is asserted.** Three alerts indicate correct rule matches for four controlled scenarios.
- The blocked chatbot event is a prepared synthetic event, while the three gateway decisions are made by real, in-process authorization logic against mock tools.
- `APPROVAL_INVALID_OR_EXPIRED` indicates an approval failed validation; the exercise explicitly creates expiry, not approval replay.
- Do **not** combine the exercise's `alerts.jsonl` with `telemetry/alerts.jsonl` or treat simulator alerts as operational dashboards.
- The runner does not change the existing security gateway, issue external refunds, call Ollama, or require Docker/ChromaDB.
- The historical ChromaDB dependency findings remain an independent open item.

Consult [`monitoring/playbooks/CYR-IR-001.md`](monitoring/playbooks/CYR-IR-001.md) for manual analyst triage steps. Human triage and risk acceptance remain outside the simulation runner.
